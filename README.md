# soma-x-server

The cloud side of SomaBox. It holds the content catalogue (curriculum files
and library books) in Postgres. SomaBox devices download content from it and push
their sync outbox (courses, grades, attendance, usage, …) to it.

Metadata is never generated by hand. Every file is indexed automatically, whichever way it arrives:

| How the file arrives | What happens |
|---|---|
| `POST /api/v1/admin/content` (upload API) | Saved, hashed, metadata extracted, row written; responds with the item |
| Copied into `content/` over SFTP/scp | The folder watcher indexes it once the upload stops growing |
| Changed while the server was down | Caught by the full scan that runs at every startup |
| Deleted from disk | Soft-deleted in the database; devices see `deleted: true` on their next sync |

What is extracted: size, sha256, MIME type, PDF page count, EPUB title and author, and
audio/video duration (needs `ffprobe`). Admin edits to title, author, description and categories
survive rescans.

## Quick start (development)

Requirements: Node 22.9+ (22 LTS), Postgres 14+, and optionally `ffprobe` (ffmpeg).

```bash
npm install
cp .env.example .env              # set DATABASE_URL and ADMIN_TOKEN (openssl rand -hex 32)
docker compose up -d              # optional: local Postgres matching .env.example
npm run dev                       # migrates the DB, scans content/, watches for changes
```

```bash
npm test                          # integration tests; needs a scratch DB:
createdb somax_test               # (or set TEST_DATABASE_URL). The suite wipes it.
```

## Content layout

```
content/
  curriculum/rwanda/   -> collection "curriculum"  (old /metadata tree, /content/<path>)
  books/               -> collection "library"     (old /library-metadata, /content/library/<id>.epub)
    science/biology/cell.epub   # folder names become default categories: [science, biology]
```

Hidden files and partial uploads (`.part`, `.filepart`, `.tmp`, `.crdownload`, `~`) are ignored.

## API

Admin endpoints need `Authorization: Bearer <token>`, using either the root `ADMIN_TOKEN` or a
**scoped API token**. Device endpoints need `Authorization: Bearer <device api key>`.

Other services, such as the staff portal, get a scoped token instead of `ADMIN_TOKEN`:

```bash
npm run token:create -- --name "staff portal" --scopes read,devices:write,content:write
```

- **`read`** covers every `GET`.
- **`devices:write`** covers registering, editing and rotating box keys.
- **`content:write`** covers uploading, editing and deleting content, and reindexing.

Every change made through the admin API is recorded in `admin_audit`: the token and, when the
caller sends an `X-Actor` header, the person it acted for. `GET /api/v1/admin/audit` lists the
changes. To revoke a token, set its `revoked_at` in `api_tokens`.

### Legacy (public; what deployed boxes call today, same response shapes as before)

| | |
|---|---|
| `GET /metadata` | Curriculum tree `[{type, name, path, size, children}]` (now also has `id`, `sha256`, `version`) |
| `GET /library-metadata` | `[{id, book_name, categories}]`. EPUBs only, because old boxes save every book as `<id>.epub` |
| `GET/HEAD /content/<path>` | Curriculum file |
| `GET /content/library/<id>.epub` | Library book |

### Boxes (`/api/v1`, the box's key)

| | |
|---|---|
| `POST /box-sync` | **Receiver for the box's sync outbox** (somabox-lms). Body: `{boxId, device, school, history, records:[{syncId, boxId, entity, op, entitySyncId, occurredAt, data}]}` → `{accepted, duplicates, rejected}` |
| `GET /sync?since=<cursor>&limit=500[&collection=]` | Content catalogue changes after the cursor: `{items, nextCursor, hasMore}`. Start at `0` and keep `nextCursor`. Items carry `sha256`, `version`, `deleted`, `downloadUrl` |
| `GET /content/:id/file` | Download any catalogue item (headers `X-Content-SHA256`, `X-Content-Version`) |
| `GET /devices/me` | The box's own record |

How the box receiver handles what it gets:

- **Stored once:** each record is kept a single time, keyed by its `syncId`, so a box can resend a batch safely.
- **Malformed records:** only those are dropped and logged. The rest of the batch is still stored, so a bad record can't stall the box's outbox.
- **Never expired:** records are kept indefinitely, as the school decided.
- **Empty batches** (`records: []`) are the box's heartbeat.
- **Every call** updates the device's box id, hardware, school and recent sync runs, and adds a row to `device_checkins`.

**Connecting a box:** run `npm run device:create -- --name "…"` here. Then on the box set
`SYNC_URL=https://<vps>/api/v1/box-sync`, `SYNC_TOKEN=<key>` and `CLOUD_URL=https://<vps>`.
What leaves the box is decided on the box's Sync page. The default is anonymous IDs, with no
names, emails or written answers.

### Admin (`/api/v1/admin`, admin token)

| | |
|---|---|
| `POST /content` | multipart: `file`, `collection`, optional `folder`, `filename`, `title`, `author`, `description`, `categories` (comma list), `overwrite=true` |
| `GET /content?collection=&q=&category=&includeDeleted=&limit=&offset=` | List/search |
| `GET /content/:id`, `PATCH /content/:id`, `DELETE /content/:id` | Read, edit metadata, or delete (removes the file) |
| `POST /reindex` | Run a full scan now |
| `POST /devices` | `{name, serial?, location?, notes?}` → `{device, apiKey}` (**the key is shown once**) |
| `GET /devices`, `GET/PATCH /devices/:id` | List, view, edit; `{"status":"revoked"}` cuts a box off |
| `POST /devices/:id/rotate-key` | Issue a new key |
| `GET /records/entities` | What boxes have sent: record counts per entity |
| `GET /records?entity=&deviceId=&after=&limit=` | The raw append-only log, oldest first (page with `after` = `nextAfter`) |
| `GET /records/current?entity=courses[&deviceId=]` | Current state of an entity across boxes: the latest record per row, without deletes |
| `GET /stats/overview` | Content totals, boxes and schools, people by role, 30-day records by entity |
| `GET /stats/usage?groupBy=day\|week\|month\|type\|role\|device\|school\|district\|course\|content&from=&to=&type=&deviceId=&district=` | Usage events from all boxes, aggregated for charts |
| `GET /stats/devices` | Per box: school, model, last seen, last sync run, pending records, learners, teachers, courses |
| `GET /stats/schools` | Boxes, learners and teachers per school (as each box's admin set it up) |
| `GET /stats/content/:id` | How a catalogue item is used on boxes (`content_opened` events) |
| `GET /stats/learners?deviceId=&school=&district=&grade=&gender=&rural=&disability=&language=&q=&limit=&offset=` | Learners (pseudonymous: learner code, no names): profile answers, school, courses, best-quiz average, outcome mastery, last active |
| `GET /stats/learners/:deviceId/:syncId` | One learner: each course with its mastery, and quiz results |
| `GET /stats/demographics` (same filters) | Counts and shares by gender, rural/urban, disability, language, grade and district, with average performance per group. Shares are of learners whose answer is known; box defaults like "prefer not to say" count as unknown unless the learner completed their profile |

Example upload:

```bash
curl -H "Authorization: Bearer $ADMIN_TOKEN" \
  -F collection=curriculum -F folder=primary-4/maths \
  -F file=@unit-3.pdf http://localhost:2999/api/v1/admin/content
```

Register a box from the shell: `npm run device:create -- --name "GS Kigali 1" --serial SBX-0001`.

## Deploying to the VPS

The full step-by-step guide is [docs/SETUP.md](docs/SETUP.md). In short:

```bash
sudo apt install -y postgresql ffmpeg
sudo -u postgres createuser -P somax && sudo -u postgres createdb -O somax somax

git pull && npm ci && cp .env.example .env   # edit .env
npm run build
pm2 start ecosystem.config.cjs && pm2 save   # migrations run on boot
```

- Run **one** instance (the ecosystem file does this), because the watcher and indexer must not run twice.
- Upload files over SFTP straight into `CONTENT_ROOT`. The watcher picks them up, so there is nothing to run afterwards.
- Behind nginx, raise the upload limit: `client_max_body_size 2g;` and `proxy_request_buffering off;`.
- On first start every existing file is hashed once, which takes a while for large video folders. The API is
  up meanwhile. Later restarts only re-hash files whose size or mtime changed.

## Database

Drizzle ORM. The schema is in `src/db/schema.ts`, and migrations are in `drizzle/` and applied on startup.
After changing the schema: `npm run db:generate`, then commit the new migration.

- `content_items`: one row per file. `version` is bumped when the bytes change; `change_seq` is bumped on any
  change and is the sync cursor; rows are soft-deleted.
- `devices`: one API key per box (only its hash is stored), plus what the box last reported: box id,
  hardware, school and recent sync runs.
- `device_checkins`: one row per box sync call, showing when each box was alive.
- `box_records`: every record boxes push (courses, enrollments, grades, attendance, usage events,
  pseudonymous users, …), append-only and keyed by `sync_id`. The current state of a row is its
  latest record by `entity_sync_id`.
